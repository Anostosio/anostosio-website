# PRIVACY-DATA-MAP — Anostosio°

Актуализировано: **03.09.2026**  
Сайт: **https://anostosio.ru/**

Цель файла — описывать **фактические** потоки данных сайта, а не предполагаемую будущую архитектуру.

## Краткая схема

```text
Посетитель
  ├─ открывает статическую страницу → хостинг / стандартные сетевые запросы
  ├─ выбирает язык → localStorage браузера
  ├─ принимает/отклоняет аналитику → localStorage браузера
  │    └─ только ACCEPT → mc.yandex.ru / Яндекс Метрика
  ├─ заполняет brief → данные остаются в браузере
  │    ├─ COPY → буфер обмена устройства
  │    └─ CREATE EMAIL → mailto: → почтовая программа
  │          └─ пользователь нажимает Send → почтовая инфраструктура → Anostosio@yandex.ru
  └─ нажимает внешнюю ссылку → Telegram / VK / HH / другой выбранный сервис
```

## Яндекс Метрика — фактическая конфигурация в репозитории

Файл: `metrika-consent.js`.

Счётчик: **110819448**.

### До согласия

- внешний `tag.js` не вставляется;
- `window['disableYaCounter110819448']` устанавливается в privacy-preserving состояние;
- аналитические цели не отправляются.

### После согласия

Инициализация включает:

```js
clickmap: true
trackLinks: true
accurateTrackBounce: true
webvisor: false
```

Передаётся только технический параметр:

```text
site_language = ru | en | es
```

Код сайта **не формирует** из полей brief параметры посетителя Метрики и не отправляет туда имя/email/текст задачи.

### После отзыва

Код:

1. сохраняет `denied`;
2. включает `disableYaCounter110819448`;
3. вызывает `ym(110819448, 'destruct')`, если счётчик уже существует;
4. удаляет вставленный сайтом tag script;
5. пытается удалить доступные домену Anostosio° first-party cookies/localStorage/sessionStorage Метрики.

Ограничение браузера: сайт не способен удалить cookie, принадлежащие непосредственно доменам Яндекса.

## Brief — фактическая модель

Файлы:

- `brief.html`;
- `en/brief.html`;
- `es/brief.html`;
- `script.js`.

Форма не содержит backend endpoint.

Алгоритм:

```text
user input
→ JavaScript reads form fields
→ buildText()
→ encodeURIComponent()
→ mailto:Anostosio@yandex.ru?subject=...&body=...
→ window.location.href = mailto
```

**Не происходит:**

- `fetch()`;
- `XMLHttpRequest`;
- POST на сервер;
- запись brief в localStorage;
- сохранение brief в собственной БД;
- отправка brief в Яндекс Метрику как значения полей.

При этом после фактической отправки письма оператор начинает обрабатывать полученное обращение. Поэтому корректная формулировка — «сайт не отправляет brief на собственный сервер», а не «персональные данные не обрабатываются».

## Правило для будущих изменений сайта

Перед подключением любого нового сервиса задать пять вопросов:

1. Какие данные он получает при **обычной загрузке страницы**?
2. Может ли он стартовать только после действия/consent пользователя?
3. Где физически обрабатываются/хранятся данные?
4. Нужно ли обновить политику и уведомление РКН?
5. Можно ли решить задачу без передачи данных третьей стороне?

Если меняется ответ хотя бы на один пункт — обновить этот файл **до production deploy**.
