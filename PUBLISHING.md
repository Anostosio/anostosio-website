# Подготовка Anostosio° к публикации

Production: **https://anostosio.ru/**  
Проект статический, без сборки. Корневой файл — `index.html`.

## Базовая публикация

1. Загружать всё содержимое репозитория с сохранением структуры `assets/`, `fonts/`, `en/`, `es/` и корневых файлов.
2. Production должен работать только по HTTPS.
3. Не менять существующие `canonical`, `hreflang`, `og:url`, `robots.txt` и `sitemap.xml` без отдельной SEO-проверки.
4. Проверять, что `Anostosio@yandex.ru`, Telegram и VK остаются актуальными.
5. После изменения структуры страниц проверять RU / EN / ES и 404.

Файл `_headers` содержит базовые заголовки безопасности и правила кэширования для платформ, которые поддерживают такой формат. Наличие `_headers` **не доказывает**, какой именно hosting provider используется в production. Фактический хостинг и его журналы должны быть зафиксированы отдельно в `LEGAL-CHECKLIST.md` / `PRIVACY-DATA-MAP.md`.

## Privacy architecture

На сайте **уже есть обработка персональных данных**, даже несмотря на отсутствие собственной серверной формы:

- Яндекс Метрика обрабатывает данные посетителей только после opt-in;
- после фактической отправки email оператор получает и обрабатывает обращение пользователя;
- инфраструктура хостинга может технически обрабатывать стандартные сетевые данные/логи.

Поэтому прежнее утверждение «политика ПДн понадобится только после подключения серверной формы» было неверным и удалено.

Актуальные публичные документы:

- `/privacy.html` — политика обработки персональных данных;
- `/legal.html` — правовая информация;
- `/en/privacy.html`, `/en/legal.html`;
- `/es/privacy.html`, `/es/legal.html`.

Внутренняя документация:

- `LEGAL-CHECKLIST.md`;
- `PRIVACY-DATA-MAP.md`.

### Brief

`brief.html` остаётся privacy-friendly статической формой:

```text
пользователь вводит данные
→ JavaScript локально собирает текст
→ создаётся mailto:
→ открывается почтовая программа пользователя
→ только после самостоятельного Send письмо поступает оператору
```

Не подключать backend / form service «для удобства» без отдельного аудита. Если появится прямая серверная отправка, CRM, база заявок, upload файлов или другой новый поток данных, **до production deploy** необходимо:

1. обновить `PRIVACY-DATA-MAP.md`;
2. обновить публичную privacy policy;
3. проверить необходимость изменения уведомления Роскомнадзора;
4. проверить локализацию и трансграничную передачу;
5. определить сроки хранения и удаления данных;
6. проверить договорные отношения с новым обработчиком.

### Yandex Metrica

Файл: `metrika-consent.js`.

Обязательные invariants проекта:

- счётчик **не загружается до consent**;
- `Accept` и `Decline` доступны без скрытого принуждения;
- отказ не запускает аналитику;
- решение можно изменить через кнопку `Cookies`;
- при отзыве сайт блокирует/останавливает счётчик и очищает доступные first-party данные Метрики;
- `webvisor: false` должен сохраняться;
- нельзя отправлять в Метрику ФИО, email, телефон, текст brief или другие идентификационные сведения через параметры/цели.

Настройки кабинета Метрики не видны в GitHub. После значимых изменений вручную проверить счётчик **110819448** по `LEGAL-CHECKLIST.md`.

## Перед production deploy

Минимальный smoke test:

- [ ] Главная / portfolio / price / brief / CV открываются в RU / EN / ES.
- [ ] Privacy и Legal открываются в RU / EN / ES.
- [ ] В новом профиле браузера до consent нет загрузки `mc.yandex.ru/metrika/tag.js`.
- [ ] `Decline` не запускает Метрику.
- [ ] `Accept` запускает Метрику.
- [ ] Повторное открытие Cookies → `Decline` останавливает дальнейшие хиты.
- [ ] `webvisor: false` сохранён.
- [ ] Privacy link виден в cookie banner.
- [ ] На brief виден privacy notice.
- [ ] `COPY ANSWERS` работает.
- [ ] `CREATE EMAIL` / «СФОРМИРОВАТЬ ПИСЬМО» по-прежнему создаёт `mailto:` и не делает HTTP POST.
- [ ] Legal/privacy ссылки доступны из интерфейса сайта.
- [ ] Нет случайно подключённых GA/GTM/Meta Pixel/сторонних form services.

Юридический deploy не заменяет организационные действия из `LEGAL-CHECKLIST.md`, в первую очередь проверку/уведомление Роскомнадзора и проверку фактического hosting / доменной идентификации.
